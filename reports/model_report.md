## Threshold 선택 근거 (Random Forest, threshold = 0.6)

### 배경

피싱 URL 탐지에서는 실제 피싱을 놓치는 **FN(미탐)**이 가장 큰 위험이므로 **Recall**이 핵심 지표다.
그러나 정상 URL을 피싱으로 잘못 차단하는 **FP(오탐)**이 과도하면 사용자 불편을 유발하고 서비스 신뢰도를 낮춘다.
기본 threshold 0.5는 오탐 방향으로 편향된 학습 데이터(정상 URL 패턴 결핍) 때문에 실제 정상 URL(`accounts.google.com` 등)을 피싱으로 잘못 판정하는 문제가 있었다.

### 선택 이유: threshold = 0.6

**① 정상 URL 오탐(FP) 감소**
- threshold 0.5 기준 FP = 9건 → 0.6에서 FP = 4건으로 **55% 감소**.
- `accounts.google.com`(피싱 확률 55.7%), `www.microsoft.com/ko-kr`(15.5%) 등 실제 정상 URL의 오탐이 해소됨.

**② Recall 하락 최소화**
- threshold 0.5 → 0.6 전환 시 Recall 0.9959 → 0.9952로 **0.0007 하락**에 그침.
- FN 증가(30 → 35건)이지만, 전체 피싱 7,353건 중 35건(0.48%) 수준으로 실용 허용 범위 내.

**③ 0.65 이상은 FN 추가 증가 없이 FP만 줄어 효과 미미**
- 0.60과 0.65는 FP·FN이 동일(FP=4, FN=35)하여 차이 없음.
- 0.70 이상에서는 FP=2로 추가 감소하나, F1-score 개선이 미미하고 경계 확률 URL의 분류 불안정성이 커짐.

**④ 9개 실사용 URL 테스트에서 유일하게 9/9 달성**
- threshold 0.5: 8/9 (accounts.google.com 오탐)
- threshold 0.6: **9/9** 전부 통과
- threshold 0.65: 8/9 (피싱 URL 1건 누락)

**결론**: Recall 손실을 최소화하면서 FP를 절반 이하로 줄이는 균형점이 **0.6**이다.
